# TOH4E / TOH4E_EM role reading

The app detects the TOH4E / TOH4E_EM DLLs as the shared `TOH4E` integration and shows `【MOD】TOH4E／TOH4E_EM設定`. Since 3.2.20, native module detection explicitly accepts `TownOfHost_ForE.dll`, `TownOfHost_ForE_EM.dll`, `TownOfHostForE.dll` and `TownOfHostForE_EM.dll`. It checks module name, path, base address, size and the selected game's PID. Loaded-module evidence takes precedence over folder-name hints; plugins detection normalizes underscores/hyphens and letter case. The detector refreshes every two seconds for late-loaded DLLs. The role reader selects the loaded CLR MOD assembly independently; it never loads or executes MOD code in BetterCrewLink.

The MOD section opens `幽霊の声が聞こえる役職設定`, a separate screen with a back button and individual toggles. There is no hardcoded role list: the reader reads `CustomRoleManager.AllRolesInfo` and each `SimpleRoleInfo.RoleName`, `CustomRoleType` and `ChatCommand`. It decodes the enum numbers against the selected DLL's own metadata. IKiller membership comes from that DLL's class/interface inheritance, joined through the class's static RoleInfo object identity, rather than its class name or namespace. Japanese ChatCommand labels are displayed; ASCII shorthand falls back to the enum name. Only Neutral/Animals definitions with verified IKiller membership appear. In the installed EM DLL checked on 2026-10-08 this yields 16 neutral and 7 animal roles, including JackalReaver. Missing metadata shows a waiting message instead of an invented list.

Impostors continue to use the existing `haunting` setting. Individual settings are saved as `tohGhostRoles`, keyed by enum name (not numeric ID), and synchronized through the authenticated host settings transport. Clients and Lite inspect this screen read-only. The public role catalogue is broadcast by the current host in lobby and during games, independently of targeted own-player roles; recipients validate sender, lobby, schema and duplicate identities. The catalogue is cleared on disconnect, host/lobby change or five seconds without refresh. Settings windows receive the same effective catalogue as the main window. First edit copies the legacy `tohNeutralKillerHaunting` value into displayed toggles and preserves saved keys from other DLL versions. An absent map retains legacy behavior only for verified Neutral/Animals killers. Crewmate killers, madmates and unknown factions never receive this permission.

Each faction section also has a bulk switch with an enabled-role count. Bulk edits affect only that faction's displayed IKiller roles, preserve other factions and saved keys from other DLL versions, and snapshot legacy defaults on first edit. Both bulk and individual switches are read-only for clients/Lite and disabled when there are no loaded role definitions.

Reference source revisions used to inspect the MOD's data structures:
- TOH4E: `402706305a6214fdcebac62a684417afb4c5f4ff`
- TOH4E_EM: `ad708fffe5d0e8e361b36d9ac4c642ba6016c427`

The setting is labeled `第三陣営・アニマル陣営のキルできる役職が幽霊の声も聞こえる`. The persisted key `tohNeutralKillerHaunting` is retained for existing settings. Eligibility now uses the actual role object in `CustomRoleManager.AllActiveRoles`: its class must implement `TownOfHostForE.Roles.Core.Interfaces.IKiller`, directly or through a base class/interface. The reader inspects metadata from the loaded DLL and associates the result with the live object's method table. It checks that the object's `MyState` is the same PlayerState being read. Class names do not need to match role enum names. This includes crewmate roles such as Sheriff and inherited `IImpostor` roles. Opportunist's IKiller membership is independent of the current `CanKill` option. Missing/unknown roles yield unknown eligibility. The older `isNeutralKiller` field remains diagnostic data only.

`SnrRoleReader.exe <pid> --toh` shares the ClrMD executable infrastructure with SNR. It selects a unique initialized `TownOfHostForE.PlayerState.allPlayerStates` dictionary, returns static slots and field/type metadata for that dictionary and `AllActiveRoles`, and decodes enum names from the selected module's DLL. The live reader follows both dictionaries each tick, validates type/player identity/counts, skips removed entries, rereads content to detect mutation, and drops stale results. No getters or game methods are invoked. Missing active role types are rediscovered after three seconds; failed discovery backs off for 30 seconds. Process/MOD reset invalidates pending results.

Vanilla clients recognize the current host's `Town Of Host For E` name suffix, including `Town Of Host For E EM v6180.383`, rich-text tags and nonbreaking spaces. The host also sends its MOD detection over the existing peer data channel. Detection persists within the same host/lobby and resets when leaving or changing hosts.

The host's BetterCrewLink sends each client **only that client's own role**. Packets include lobby, client and player IDs; only the current host can supply them. A successful write is required before recording a sent value. Roles are sent again when the data channel opens or reconnects, on role changes and at one-second intervals. Missing roles are explicitly revoked, clients expire roles after five seconds without refresh, and round/lobby changes clear received roles. The host and clients must all run this updated BetterCrewLink; clients do not need the TOH4E game MOD. Without the host's BetterCrewLink or a readable host role, no IKiller audio permission is inferred from the vanilla substitute role.

TOH4E-family impostor classification requires both the original vanilla `isImpostor` and the loaded DLL's `CustomRoleType === 'Impostor'` for the player's MainRole. There is no impostor name whitelist. `src/common/Impostor.ts` applies this only to `TOH4E`; vanilla, SNR and NoS retain their existing behavior. The reader preserves the original bit as `vanillaIsImpostor` before replacing effective `isImpostor`. Audio, radio authorization/partners, vision hearing and UI share this classification. Own-role packets carry the player's faction and player/client identity plus an impostor boolean for other players, without revealing their assigned role names. Clients accept these only from the current host in valid targeted packets, while their own-role result is fresh (five seconds). Missing, unknown or expired faction information grants no impostor permission, including old packets without CustomRoleType. New roles work automatically when registered by the loaded DLL.

Settings and debug windows use the same effective MOD/role state as audio. The realtime view shows role name, numeric role ID, `IKiller` (true/false/unknown), Opportunist.CanKill when applicable, and whether the role came from the local MOD or the host's BetterCrewLink.

The reader now builds x86 and x64 executables; discovery uses the game's architecture and live memory reads use the reported pointer size. Tests: `powershell -File scripts/build-snr-reader.ps1`, `node scripts/test-toh-reader.mjs`, `node scripts/test-toh-reader.mjs --x64`, `node scripts/test-toh-ghost-roles.mjs`, `node scripts/test-toh-sync.mjs`, `node scripts/test-mod-settings.mjs`, `node scripts/test-toh-installed.mjs <running-game-pid>` (x64 by default, `--x86` for x86), `npm run typecheck`, `npm run check:nesting`. Both fixtures verify DLL enum numbers differing from production, class names/namespaces differing from faction, newly added roles, IKiller inheritance, role/option changes, dictionary removals/replacement, GC, unknown IDs and process isolation. Transport tests run production methods with a host and three simulated clients, including catalogue validation/expiry, role delivery and impostor radio. The installed-DLL test captures the actual running MOD, validates its live-memory layout, checks impostor and audio predicates for every registered role, and renders both editable and read-only switches. The installed x64 EM process yielded 149 registered roles and 23 eligible settings on 2026-10-08; gameplay voice behavior remains unverified.
