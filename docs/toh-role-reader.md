# TOH4E / TOH4E_EM role reading

Both currently publish the assembly `TownOfHost_ForE.dll`. The app detects this or `TownOfHost_ForE_EM.dll` as the shared `TOH4E` integration and shows `【MOD】TOH4E／TOH4E_EM設定`. The new `tohNeutralKillerHaunting` toggle defaults off and follows the existing host-owned lobby settings synchronization (including Lite).

The MOD section now opens `幽霊の声が聞こえる役職設定`, a separate screen with a back button and individual toggles for 15 neutral and 7 animal IKiller roles. Impostors continue to use the existing `haunting` setting. Individual settings are saved as `tohGhostRoles`, keyed by enum name (not numeric ID), and synchronized through the same authenticated host lobby settings transport. Clients and Lite can inspect this screen read-only. When first edited, the screen copies the legacy `tohNeutralKillerHaunting` value into all individual toggles before applying the edit. An absent map retains compatibility with older saved settings and hosts. Once a map exists, only explicitly enabled supported neutral/animal roles with verified IKiller membership receive permission; crewmate killers, madmates and unknown roles do not. Vanilla impostor substitute roles never override an individual off toggle. The list was checked against TOH4E_EM upstream main; newly added roles require updating `src/common/TohGhostRoles.ts`. `node scripts/test-toh-ghost-roles.mjs` verifies every listed role's on/off audio behavior, legacy migration, impostor independence and read-only rendering.

Reference source revisions used to inspect the MOD's data structures:
- TOH4E: `402706305a6214fdcebac62a684417afb4c5f4ff`
- TOH4E_EM: `ad708fffe5d0e8e361b36d9ac4c642ba6016c427`

The setting is labeled `第三陣営・アニマル陣営のキルできる役職が幽霊の声も聞こえる`. The persisted key `tohNeutralKillerHaunting` is retained for existing settings. Eligibility now uses the actual role object in `CustomRoleManager.AllActiveRoles`: its class must implement `TownOfHostForE.Roles.Core.Interfaces.IKiller`, directly or through a base class/interface. The reader inspects metadata from the loaded DLL and associates the result with the live object's method table. It checks that the object's `MyState` is the same PlayerState being read. Class names do not need to match role enum names. This includes crewmate roles such as Sheriff and inherited `IImpostor` roles. Opportunist's IKiller membership is independent of the current `CanKill` option. Missing/unknown roles yield unknown eligibility. The older `isNeutralKiller` field remains diagnostic data only.

`SnrRoleReader.exe <pid> --toh` shares the ClrMD executable infrastructure with SNR. It selects a unique initialized `TownOfHostForE.PlayerState.allPlayerStates` dictionary, returns static slots and field/type metadata for that dictionary and `AllActiveRoles`, and decodes enum names from the selected module's DLL. The live reader follows both dictionaries each tick, validates type/player identity/counts, skips removed entries, rereads content to detect mutation, and drops stale results. No getters or game methods are invoked. Missing active role types are rediscovered after three seconds; failed discovery backs off for 30 seconds. Process/MOD reset invalidates pending results.

Vanilla clients recognize the current host's `Town Of Host For E` name suffix, including `Town Of Host For E EM v6180.383`, rich-text tags and nonbreaking spaces. The host also sends its MOD detection over the existing peer data channel. Detection persists within the same host/lobby and resets when leaving or changing hosts.

The host's BetterCrewLink sends each client **only that client's own role**. Packets include lobby, client and player IDs; only the current host can supply them. A successful write is required before recording a sent value. Roles are sent again when the data channel opens or reconnects, on role changes and at one-second intervals. Missing roles are explicitly revoked, clients expire roles after five seconds without refresh, and round/lobby changes clear received roles. The host and clients must all run this updated BetterCrewLink; clients do not need the TOH4E game MOD. Without the host's BetterCrewLink or a readable host role, no IKiller audio permission is inferred from the vanilla substitute role.

TOH4E-family impostor classification now requires both the original vanilla `isImpostor` and a recognized impostor `MainRole` name. `src/common/Impostor.ts` applies this rule only to `TOH4E`; vanilla, SNR and NoS retain their existing behavior. The reader preserves the original bit as `vanillaIsImpostor` before replacing the effective `isImpostor`. Audio, radio authorization/partners, vision hearing and effective UI state share this classification. Own-role packets also carry player/client identity plus an impostor faction boolean for every connected player, without disclosing other players' role names. Clients accept these flags only from the current host in a valid targeted own-role packet, and use them only while the own-role result is present and fresh (five seconds). Missing, unknown or expired role information grants no impostor permission. Updating the recognized enum names is required when upstream adds an impostor role. The transport test verifies actual impostor radio partners, exclusion of substitute-role neutrals, packet validation and expiry; the individual-role test verifies TOH-only scope and both halves of the conjunction.

Settings and debug windows use the same effective MOD/role state as audio. The realtime view shows role name, numeric role ID, `IKiller` (true/false/unknown), Opportunist.CanKill when applicable, and whether the role came from the local MOD or the host's BetterCrewLink.

The owned x86 fixture verifies actual IKiller interfaces and inheritance, class/enum name differences, role/option changes, dictionary removals/replacement, GC, unknown role IDs, and process isolation. The transport test runs production controller methods with a host and three simulated clients to verify delivery, reconnects, role loss, expiry, sender validation, ghost audio and lobby/round/host changes. Real TOH4E/EM host/client gameplay validation remains required.
